`cd75ef56a2d9194f98fe2c9c6dbd00e2f3ede05b` (V4.50–V4.58).

## Kept and replaced

- Kept the AI activity/approval/completion hover card and separate AI details tab while migrating all music references to upstream's shared `Player`.
- Adopted shared `Stats` and `BarSvc`, extra-screen bars, and main-only island/calendar script triggers. VPN stays at settings page 36; Gaming opens Window rules at 37. The background visualizer and German presets remain unchanged.
- Replaced the fork's extra lockscreen `Player.qml` with upstream `LockPlayer.qml`. Their media selection, controls, position timer, and formatting implementations are the same; the lock view now instantiates the upstream component. Other fork-bundled lockscreen components remain necessary.
- Adopted upstream's installer/library change detection and cleaned terminal environment. Kept the stricter fixed fork-main fetch and fast-forward-only update policy: dirty, unreadable, off-main and diverged checkouts are refused, never stashed/reset. Managed updates resolve the fetched commit to a SHA before merging. Git worktrees are supported in both update paths.
- ZIP conversion clones fork `main` beside the actual ZIP folder and preserves the original. It does not rename a separate checkout, and unattended input does not consent to conversion.
- Adopted upstream's keyboard retention, exact niri refresh rates, restored lockscreen and removal of the old hot-corner panel. The fork's hot-corner preset was already disabled.

## Integration fixes verified by regression tests

- On Qt 6.8.2, changing an `Instantiator` numeric model from 1 to 0 left the delegate and shared-service reference alive. `active` now controls holders, with a constant model of 1. The final visible surface releases Player/Stats and polling stops.
- `hypr-set` holds its write lock while invoking `rice-niri`. Upstream's new keyboard remembrance called back into `hypr-set` and waited on that lock. The caller now remembers the keyboard in-process without recursively applying, then explicitly skips the child's repeat check. A temporary-HOME test checks that an ordinary niri setting change finishes promptly and keeps a German keyboard.
- Terminal launch throttling is protected by a lock, including simultaneous/repeated requests. A failed launch can be retried. Dry-run does not compact the installed checksum history.

## Checks and boundaries

Local checks: 82 Python tests, three login-scale Python tests, ten login Qt tests,
eight shared-service/AI Qt tests, ShellCheck, 26 existing security checks, compilation
of 45 Python entrypoints, publication scan, installer dry-run, and `git diff --check`.
The CI workflow runs the same Qt regression harness plus both NixOS profile evaluations.
Remote CI must pass on the exact published head before merging.

The new Qt tests run the production Player, LockPlayer, Stats, StatsHold and BarSvc
against mock Quickshell/MPRIS services. AI state expressions and request handling
are extracted from the production island. They do not claim a rendered Quickshell
Wayland session, physical monitor test, real PAM authentication, ISO build or deployment.

Upstream's extra-screen support still copies horizontal `Bar`, not `VBar` for left/right
positions; desktop-click dismissal of extra-screen cards is not provided by its main-bar
click catcher. These are limitations of the new optional upstream feature, not removed
fork behavior. A real multi-monitor Wayland session is still needed to validate those
flows visually. The existing primary bar, AI logic and script routing are covered here.
